# Codex 开场提示词（可直接粘贴）

> 用途：粘到 Codex 会话开头，让它在当前 thread 里立刻切到「留痕 + 可交接」模式。
> 如果项目根已有 `AGENTS.md`，Codex 会自动读，这段可以省掉；换用别的 AI 工具时这段仍然适用。

---

```text
在神罚（strict-ledger）项目里工作，从现在起遵守三条：

1. 每轮结束必须留痕。
   向 docs/handoff/YYYY-MM-DD.md 追加一段（当天文件不存在就新建，只追加不覆盖），固定五行：
   - 做了什么：动作，不是意图
   - 为什么：决策依据，包括被你否掉的方案和否掉的原因
   - 验证：跑了什么命令、结果如何；没跑就写没跑
   - 没做：明确排除的范围
   - 下一步：待决事项或阻塞点
   「为什么」不许写"为了实现需求"这种废话，要写能被人复用的判断。

2. 完成一个可独立验证的功能点后，给我一条提交建议（改了什么/为什么/验证结果），
   等我点头再 commit。不攒到最后一次性提交，也不每改一个文件提一次。
   提交信息中文，一次一件事，不把不相关的改动塞进同一次提交。

3. 汇报只说五件事：改了哪些文件、为什么改、怎么验证的（贴原始输出）、怎么回滚、遗留风险。
   先结论后理由，不复述我的问题。

另外三条项目硬约束：
- src/core 里不许出现任何 react / react-native import，它是纯函数层。
- 没真跑过的测试不许说"测试通过"；Release APK 用的是 debug 签名，只能测试不能分发。
- 改 android/ 原生代码、app.json 版本字段、magisk/ 脚本之前先问我。

最后提醒你一个现状：这个仓库只有 1 个 commit，0.2.0 和 0.3.0 的成果全是未提交的工作区改动。
在你接手期间不要再往上叠加不相关的东西，每个改动都要说清属于哪一块。
```

---

## 关于第 2 条的授权边界

全局规范里 `git commit` 属于"必须先问"。这里保留了这个边界，只要求 Codex **主动提议**、不自动执行。

如果你想让它在某些条件下直接提交（比如"只在 docs/ 和测试文件的改动上自动提交"），把第 2 条改成：

```text
2. 完成一个可独立验证的功能点后，直接提交，不需要问我。前提：
   - 提交前 npm test 和 npm run typecheck 都通过，并把原始输出贴给我
   - 一次提交只包含一件事，中文信息说清做了什么和为什么
   - 涉及依赖、CI、app.json 版本号、android/ 原生代码、magisk/ 脚本的改动不在此列，仍需先问我
```

这是放宽授权，只在你自己确认过的情况下启用。
