## 为什么被取代

原方案（往 `docs/handoff/YYYY-MM-DD.md` 每轮追加）有一个致命弱点：**它依赖模型自觉**。

模型忘了写、写空话、写到一半被打断，记录就没了，而且事后补不回来——因为对话上下文已经不在。

codelog 换了事实源：直接解析 Codex 自己写的 `~/.codex/sessions/**/rollout-*.jsonl`，加上磁盘指纹对账。这两样**不依赖模型是否配合**——即使 Codex 一个字都没记，事后跑一次 `sync` 也能补齐历史。这是架构级的差别，不是实现细节。

## 唯一被继承的判断

原方案里「按任务轮次、不按文件」的粒度，codelog 的 `SKILL.md` 采纳了同一结论（"不要每改一个文件就跑一次；一轮改动跑一次就够"）。

原因仍然成立：一次重构动 20 个文件，按文件记会拆成 20 条孤立记录，整体决策信息丢失。

## 现在的做法

| 环节 | 由谁负责 | 是否依赖模型自觉 |
|---|---|---|
| 谁在何时调了什么工具、动了哪些文件 | codelog `sync`（解析会话日志） | 否 |
| 磁盘上真实发生什么增删改 | codelog `scan`（指纹对账） | 否 |
| 为什么改、怎么验证、怎么回滚 | codelog `summary` | **是**，唯一的一处 |

`summary` 这个缺口没法用工具补——会话日志里没有"意图"。所以整套留痕的可靠性上限，就卡在模型愿不愿意如实填 summary 上。
