# 第 2 条任务说明：工资与考勤引擎

> 状态：口径已定，待用户确认一处矛盾后开工。
> 目标：让 App 知道「今天你到底赚了多少钱」，而不是现在那个手填的死数 `settings.monthlyIncome`。

## 1. 为什么这是地基中的地基

首页的「今日可花」、目标页的「每日应存」、待还页的「缺口折合几小时工作」，全都在用一个固定月薪推算。

一旦加上第 3 条神罚模式、第 4 条状态栏、第 5 条算力分析，它们问的都是同一个问题：**我到底赚了多少？** 这个数现在答案是错的。

## 2. 已定口径

| 项 | 选择 |
|---|---|
| 计薪天数 | 按**当月实际应出勤**，时薪随月份变化 |
| 加班 | 工作日延时**只记时长，不折算钱** |
| 工资口径 | **到手实发**（填税后金额，不自动算个税社保） |
| 试用期 | 与转正**分开设**，按日期自动切换 |

### 2.1 你的实际参数（写进默认配置和测试用例）

| 项 | 值 |
|---|---|
| 试用期 | **2026-10-10 至 2026-11-09**，转正日 **2026-11-10** |
| 试用期底薪 | **5000**（到手，无任何补贴） |
| 转正后底薪 | **5000**（是否上调待确认，见 §10） |
| 餐补 / 全勤 | **500 / 200，转正后发放**，与底薪分开记账 |
| 月休天数 | **4** |
| 每日工时 | **8 小时**，排班 **18:00 → 次日 02:00（跨午夜）** |
| 工资周期 | **每月 10 号 ~ 次月 9 号**（按入职日对月，不是自然月） |
| 发薪日 | **周期结束后第 5 天**，即 15 号 |
| 餐补 | **500 / 月，固定**，仅转正后发放 |
| 全勤奖 | **200 / 月**，仅转正后发放，需达成全勤 |
| 加班 | 有奖金但规则未知 → **本期只记时长，不折算金额** |

按这套参数算：周期 1（31 天）应出勤 27 天，日薪 = 5000 ÷ 27 = **185.19**；转正满勤到手 = 底薪 5000 + 餐补 500 + 全勤 200 = **5700**。

**口径铁律（这条最容易写错）**：`日薪 = 底薪 ÷ 应出勤`，**补贴和全勤不参与日薪计算**。它们是在底薪之外另加的整笔钱。
如果把 5700 当地薪基数去算日薪，全勤没达成的月份就扣不回来了。

## 3. 一处待你确认的拆分

你的原话是「休息的四天如果上班则也加工资」，但选项选了「加班不折算钱」。本说明按下面这样拆分，如果不对请先改这条：

| 场景 | 处理 |
|---|---|
| **休息日上班** | 你自己找的活，照样算一天正常出勤，**多拿一天日薪** |
| **转正后加班奖金** | 规则未知，**先不计算**；只记录起止时间和时长，等规则明确后再加奖金项 |
| **试用期内的延时** | 只记时长，不折算（试用期没有加班奖金这回事） |

## 4. 数据模型

### 4.1 工资配置（挂在 Settings 下，不新增根字段）

```
Settings.work: WorkProfile
  monthlyIncome: number          转正后月到手
  probationIncome?: number       试用期月到手
  probationEndDate?: string      转正日 YYYY-MM-DD
  restDaysPerMonth: number       每月休息天数，默认 4
  workHoursPerDay: number        每天工时，默认 8
  payday: number                 发薪日，默认 15
  cycleStartDay: number          **工资周期起始日，默认 10**（每月 10 号到次月 9 号为一个周期）
  fullAttendanceBonus?: number   全勤奖金额
  allowances: Allowance[]        补贴项
```

```
Allowance
  name: string                   补贴名称（餐补、交通补…）
  amount: number                 金额
  mode: 'per-day' | 'fixed'      per-day 按出勤天数×金额，fixed 每月固定
  phase: 'probation' | 'regular' | 'both'   何时生效，默认 'regular'
```

`phase` 字段是必须的：你的餐补和全勤都是**第二个月才开始**，试用期只有 5000，不能把 500+200 也算进去。

### 4.2 考勤（新增根字段）

```
LedgerState.attendance: AttendanceRecord[]

AttendanceRecord
  date: string      YYYY-MM-DD（本地时区，不是 UTC 截断）
  clockIn?: string  ISO 时间
  clockOut?: string ISO 时间
  status: 'worked' | 'rest' | 'leave'
  note?: string
```

`normalize.ts` 要给老数据补默认值：`attendance: []`、`settings.work: 默认配置`。

## 5. 计算规则（写死，不许自由发挥）

**先记住一件事：工资周期不是自然月。**你的工资按「每月 10 号到次月 9 号」发，所以下面所有「本期」都指这个周期，不是 1 号到 30 号。

```
周期起点 = 本月 cycleStartDay 号
周期终点 = 次月 (cycleStartDay − 1) 号
周期天数 = 起点到终点（含两端）

当期月薪 = 周期起点 < probationEndDate ? probationIncome : monthlyIncome
周期应出勤 = 周期天数 − restDaysPerMonth
日薪 = 当期月薪 ÷ 周期应出勤
时薪 = 日薪 ÷ workHoursPerDay

周期已赚 = 周期内已确认出勤天数 × 日薪
全勤达成 = 周期内休息天数 ≤ restDaysPerMonth（休息 5 天及以上直接没有全勤）
周期补贴 = Σ 生效中的 per-day 项(amount × 出勤天数) + Σ 生效中的 fixed 项(amount)
周期预计到手 = 周期已赚
             + (转正 && 全勤达成 ? fullAttendanceBonus : 0)
             + 周期补贴
```

**全勤的判定是「休息天数」，不是「出勤天数」**：月休 4 天的人，休息 5 天就没全勤，哪怕你加班补上了出勤也不给——这是你原话「多余休息就没有全勤」的意思。`leave`（请假）计入休息天数。

**「生效中」的定义**：`allowance.phase === 'both'` 或 `phase === (周期起点 < probationEndDate ? 'probation' : 'regular')`。全勤奖只在转正后发放。

### 5.1 跨午夜班次（你的排班是 18:00 → 次日 02:00）

这是本期最容易算错的地方，规则写死：

| 规则 | 说明 |
|---|---|
| **归属日 = 上班打卡那天的日期** | 18:00 打卡在 10-18，次日 02:00 下班，这条记录归 **10-18**，不归 10-19 |
| **时长 = clockOut 时间戳 − clockIn 时间戳** | 跨天由时间戳自然处理，不要手工加 24 小时 |
| **未确认下班不跨天自动结转** | 10-18 只打了上班卡没打下班卡，10-18 就是「未完成」，不算钱，也不会自动记到 10-19 |
| **凌晨确认下班要归到前一天** | 02:00 打开 App 点「下班确认」时，要能识别昨晚那个未完成的班次，把 clockOut 写进 10-18 那条记录 |

UI 展示：

```
10月18日 18:00 → 次日 02:00   已确认   ¥185.19
```

**禁止**用 `toISOString().slice(0,10)` 判断归属日——那是 UTC，凌晨 00:00–08:00 之间会算成前一天。必须用本地日期构造。

### 5.2 你的工资周期（全部算法的基础）

工资按「每月 10 号到次月 9 号」发，**不是自然月**。你的实际周期：

| 周期 | 区间 | 天数 | 阶段 | 应出勤 | 日薪（底薪口径） | 满勤到手 |
|---|---|---|---|---|---|---|
| 1 | 2026-10-10 ~ 11-09 | 31 | 试用期 | 27 | 5000 ÷ 27 = **185.19** | **5000** |
| 2 | 2026-11-10 ~ 12-09 | 30 | 转正 | 26 | 5000 ÷ 26 = **192.31** | **5700** |
| 3 | 2026-12-10 ~ 2027-01-09 | 31 | 转正 | 27 | 5000 ÷ 27 = **185.19** | **5700** |
| 4 | 2027-01-10 ~ 02-09 | 31 | 转正 | 27 | 185.19 | **5700** |

三条推论，必须遵守：

1. **周期 1 是完整的 31 天**，所以「第一个月拿满 5000」是按周期算出来的自然结果，不需要按比例折算。
2. **日薪每期都不一样**（30 天周期 192.31，31 天周期 185.19，差 7 元左右）。**不许用固定日薪**。
3. **11-10 就是周期 2 的起点**，所以不存在「11 月混合月」——试用期在 11-09 整整齐齐结束。

**满勤到手 = 底薪 + 餐补 + 全勤**，但**日薪基数只有底薪**。这两列必须分开算：`日薪 × 应出勤` 永远等于底薪，不会因为加了补贴而变大。

**发薪日**：周期结束后第 5 天（周期 1 在 11-15 发）。

**如果某期出勤不足**：`已赚` 会低于满勤额，全勤奖自然没有；底薪部分**按出勤折算，不补足**。

**③ 两个数要分开，别混成一个**

| 字段 | 含义 | 用途 |
|---|---|---|
| `cycleEarned` | 本周期已赚（已确认出勤天数 × 日薪） | 首页「今天赚了多少」的累计 |
| `cycleExpected` | 满勤应得（日薪 × 应出勤 + 补贴 + 全勤） | 「这期能拿多少」 |

满勤时两者相等；缺勤时 `cycleEarned` 低于 `cycleExpected`，差额就是缺勤扣掉的钱。

UI 示例：

```
今天赚了 ¥185.19          ← 日薪
本周期已赚 ¥3,703.70      ← 已出勤 20 天
满勤应得 ¥5,000.00        ← 还差 7 天
```

**不许**用 `cycleEarned ÷ 已出勤天数` 倒推日薪——日薪只能由「当期月薪 ÷ 应出勤」算，反过来算会把误差放大。

关键约束：

- **只有 `status='worked'` 且 `clockOut` 有值的那天算已赚**。打了上班卡没打下班卡 = 不算钱，宁可少算也不虚高。
- **休息日上班（`status='worked'`）照样算一天日薪**，并且计入出勤天数——它同时帮你达成全勤。
- 日期一律用**本地时区**构造和比较，禁止 `toISOString().slice(0,10)`（现有代码在 `LedgerScreen` 就踩了这个坑，记账时间显示早 8 小时）。
