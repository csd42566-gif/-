# Android 通知连接与 Root 状态检测

## 目标

在中国大陆 Android 首版中，从用户主动授权的系统通知识别支付宝、微信支付和短信 App 交易提醒；识别结果只进入账本待确认队列。提供独立的 Root 状态检测，不制作 Magisk 模块，不访问其他 App 私有数据。

## 用户流程

1. 设置 -> 银行与支付平台，用户查看支持范围并跳转 Android 通知使用权设置。
2. Android 通知监听服务仅接收允许来源包名的通知，立即解析成金额、收支方向、商户/摘要、时间和来源；原始通知正文不落盘、不进日志。
3. JS 解析层校验字段并生成候选交易；匹配现有交易/待确认记录时丢弃重复项。
4. 候选项显示在账本待确认列表；用户选择账户、编辑信息并确认后才更新余额。识别失败的通知不入账。

还款识别补充：花呗、白条、信用卡及借贷平台的成功还款进入 `repayment`；识别到“代某人还款”时进入 `proxy-repayment` 并保留有限的对象提示；待还提醒进入 `repayment-reminder`，失败通知进入 `repayment-failed`。提醒和失败状态只进入待确认队列，不得直接扣减账户或欠款。成功还款确认时必须选择对应欠款，交易入账与欠款金额扣减作为一次领域操作执行，欠款金额最低为 0。
5. Root 增强页面显示“已检测到 / 未检测到 / 检测不可用”，可刷新；检测只检查常见 su/Magisk 安装标志，不执行 su 命令，不据此授予额外权限。

## 边界与隐私

- 不申请 READ_SMS、RECEIVE_SMS，不读取短信数据库；短信仅限短信 App 自己发布且用户已授权读取的系统通知。
- 不保存银行或支付平台密码，不模拟登录，不调用商户账单接口作为个人账单授权。
- 来源以系统包名允许名单识别；设置中提供启用/停用总开关。默认关闭，用户主动授权后启用。
- 暂不承诺杀进程、厂商后台限制下的即时性；重新打开 App 时可拉取原生服务保存的最小候选事件。
- 日志不包含通知正文、完整账户号、凭证或原始 payload。

## 架构

- Kotlin NotificationListenerService 负责通知权限状态、来源过滤、轻量抽取与最小候选暂存。
- React Native 原生模块负责读取授权状态、打开系统设置、读取并清除候选队列、Root 状态检测。
- src/integrations/notifications 负责 payload 校验、来源/格式识别和候选映射；不依赖 React Native。
- src/features/ledger 负责默认账户选择和人工确认，复用现有 queueDetectedTransaction。
- 设置页面展示连接开关、授权状态和 Root 状态。

## 验收标准

- 未授权时不接收通知；启动授权设置不改变账本数据。
- 白名单中明确支持格式的通知产生一个候选项，重复通知不重复排队；未知或无金额通知不产生交易。
- 候选项待用户选择账户并确认后才更新余额；忽略候选项不会改变余额。
- Root 检测不执行 shell/su，不影响非 Root 设备使用。
- Jest、类型检查、Android Debug 构建通过；安装更新不清除现有设备数据。
