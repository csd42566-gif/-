# 还款与代还通知识别规格

## 目标

在现有 Android 通知识别基础上，识别主流支付/账单 App 的平台还款和“替别人还款”通知，并把结果放入待确认队列。用户确认前不修改账户余额、交易或欠款。

## 范围

第一版覆盖：

- 支付宝、微信支付及已支持短信 App 的还款成功、还款失败、待还提醒。
- 通知中明确表达“替他人/代还/帮还”的支出候选。
- 可匹配现有 `Debt`，匹配失败时保留候选并要求用户选择。
- 保留来源 App、识别事件类型、服务商、对象提示和状态等最小字段。

第一版不覆盖：

- 读取其他 App 私有数据库、模拟登录、代替用户发起支付或还款。
- 直接银行 API 授权、密码保存、自动扣款。
- 仅凭金额自动确认或自动减少欠款。

## 识别模型

通知原生层根据来源包名和通知标题/摘要生成最小事件：

- `payment`：普通支付/消费。
- `repayment`：本人信用卡、花呗、白条、借贷等还款成功。
- `proxy-repayment`：替他人、代还、帮还成功。
- `repayment-reminder`：应还、待还、还款日提醒。
- `repayment-failed`：还款失败。

状态、金额、服务商和对象提示进入 JS 层；原始通知正文不落盘、不进入日志。

## 入账规则

- `repayment` 和 `proxy-repayment` 默认按支出候选处理，用户选择扣款账户后确认。
- 确认还款时，如果关联 `debtId` 有效，按还款金额减少欠款余额，最低为零。
- 还款金额超过欠款余额时不自动截断交易金额，只把欠款余额置零并提示超额。
- `repayment-reminder` 和 `repayment-failed` 只进入提醒候选，不得直接写入交易。
- 所有候选继续使用现有指纹去重规则；来源、事件类型、金额和分钟组成候选指纹。

## 隐私与安全

- 仅监听用户明确授权的系统通知。
- 来源 App 通过包名白名单识别；未知来源不入队。
- 不申请 `READ_SMS` / `RECEIVE_SMS`，不读取短信数据库。
- 不保存完整通知正文、完整卡号、凭证或密码。

## 验收标准

1. 还款成功通知归一化为 `repayment`，金额和服务商正确，原文不被保留。
2. “替张三还款”通知归一化为 `proxy-repayment`，保留有限对象提示。
3. 还款提醒和失败通知不会直接成为交易。
4. 确认已匹配欠款的还款后，账户余额和欠款余额同时正确变化。
5. 无账户或无效欠款时，确认操作抛出明确错误且候选仍保留。
6. 现有普通消费通知、手工记账、转账和旧账本迁移测试不回归。
