# 代还导入设计

## 目标

在“代还”页面增加一个可审阅的导入入口，允许用户把抖音、支付宝、微信、得物、京东等平台的账单或还款通知文本转换为待确认代还记录，避免重复记账，并复用现有欠款和账户确认流程。

## 范围

- 首版支持用户粘贴文本并选择来源平台。
- 支持通过 Android 分享文本进入导入页面的业务接口；本轮不新增原生分享接收页面。
- 支持平台：抖音、支付宝、微信、得物、京东、其他。
- 导入结果进入 `pendingTransactions`，不能绕过用户确认直接入账。
- 确认时必须选择有效账户；代还记录必须绑定有效欠款。
- 导入记录使用 `source: 'import'`，并保留来源平台、原始摘要、识别置信度。
- 使用稳定指纹去重，重复导入不增加待确认记录。

## 不在范围内

- 读取其他 App 私有数据库或绕过 App 权限。
- 首版截图 OCR、自动登录平台、自动发起还款。
- 新增第三方依赖。

## 数据流

1. `DebtsScreen` 打开“导入代还”弹窗。
2. 用户选择平台并粘贴文本。
3. 平台解析器提取金额、时间、代还对象和摘要，输出标准化导入候选。
4. 业务层校验候选并转换为 `PendingTransaction`。
5. 业务层调用现有队列逻辑去重后写入 `pendingTransactions`。
6. 账本页现有待确认流程负责选择账户、绑定欠款和确认入账。

## 模块边界

- `src/features/repayment-import/parsers.ts`：只负责文本解析和平台规则，不依赖 React 或存储。
- `src/features/repayment-import/repaymentImport.ts`：负责候选校验、标准化、去重和写入状态。
- `src/features/repayment-import/RepaymentImportSheet.tsx`：负责输入和预览，不直接修改账户或欠款。
- `src/features/debts/DebtsScreen.tsx`：只负责入口和状态回调。
- `app/index.tsx`：负责将导入后的状态保存到现有账本状态。

## 解析规则

- 金额必须是大于 0 的人民币金额，支持 `¥123.45`、`123.45元`、`金额：123.45` 等常见形式。
- 时间优先识别 `YYYY-MM-DD HH:mm`、`YYYY/MM/DD HH:mm`、`YYYY年M月D日 HH:mm`，缺失时间使用导入时间。
- 代还对象优先从“代还/帮还/替还/偿还”附近提取；提取不到时保留为空，由用户在确认时选择欠款。
- 只有包含还款语义且金额可识别的文本才生成候选。
- 解析失败返回用户可见错误，不生成半成品记录。

## 错误和安全

- 不记录完整原始文本到日志；界面可展示摘要，日志只记录平台、结果和金额区间。
- 不把无法确认的记录自动当作支出或还款。
- 导入失败不改变现有账本状态。

## 测试要求

- 每个平台至少一个成功解析用例。
- 金额、时间和代还对象提取用例。
- 普通消费文本和无金额文本被拒绝。
- 重复导入不产生第二条待确认记录。
- 导入结果的 `source`、`eventKind` 和 `eventStatus` 正确。
- 全量 Jest、TypeScript 检查和 Android release 构建通过。
